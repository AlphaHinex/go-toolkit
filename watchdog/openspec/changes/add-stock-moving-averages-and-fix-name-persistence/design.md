## Context

当前股票通知流程在触发阈值后仅输出价格、趋势与区间信息。基金侧已经具备阶段性高低位相关信息，股票侧需要补齐常用技术参考（MA）以提高通知有效性。另一个现存问题是股票名称虽可在抓取时获得，但在持久化阶段未稳定回写，导致 YAML 中 `name` 字段不可靠。

## Goals / Non-Goals

**Goals:**
- 在股票通知中提供常用股票周期（5/10/20/60/120/250）的统计信息。
- 在通知中按周期逐行展示最小值、最大值、MA 均值，并标识当前价格相对 MA 的位置关系，帮助快速判断强弱。
- 确保 `stocks.<code>.name` 在获取到有效名称时被写回并持久化到 YAML。
- 当名称获取失败时不清空已有名称。

**Non-Goals:**
- 不引入复杂技术指标（如 MACD、KDJ、布林带）。
- 不改变现有股票筛选规则与触发阈值逻辑。
- 不新增配置项来自定义 MA 周期（本次固定常用周期）。

## Decisions

1. MA 计算来源于已存在的股票历史收盘价序列。
- 方案：在股票历史数据中按周期计算简单移动平均（SMA）。
- 原因：数据已可得，计算成本低、可解释性强。
- 备选：外部接口直接读取 MA。未采用原因：增加外部依赖与不稳定性。

2. MA 展示遵循“可用即展示，缺失即标记”。
- 方案：当历史数据不足某周期时，该周期行输出占位（如 `250日：N/A`）。
- 原因：避免误导并保持格式稳定。
- 备选：隐藏不可用 MA。未采用原因：通知格式波动大，不利于对比。

3. 名称持久化采用“新值覆盖空值，失败保留旧值”。
- 方案：在每轮股票处理后，将抓取到的非空名称写回 `persistedStock.Name`。
- 原因：兼顾准确性与容错。
- 备选：始终覆盖。未采用原因：接口异常时可能写入空值污染配置。

## Risks / Trade-offs

- [历史数据不足导致长周期 MA 不可用] -> 输出稳定占位并在测试中验证。
- [通知文本变长导致可读性下降] -> 采用固定周期顺序与简洁单行格式，每个周期独占一行。
- [名称来源异常导致脏数据] -> 增加非空校验与保留旧值策略。

## Migration Plan

1. 在 `product/stock.go` 增加分周期 min/max/MA 计算与格式化输出能力。
2. 在 `watchdog.go` 的股票持久化分支补充名称回写逻辑。
3. 更新/新增测试覆盖 MA 文本与名称持久化。
4. 运行现有测试并校验 YAML 输出兼容性。

回滚策略：
- 回滚 `watchdog.go` 与 `product/stock.go` 的相关提交，可恢复到仅价格通知与原持久化行为。
